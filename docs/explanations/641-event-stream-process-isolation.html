PR #641: Per-Process Log Stream Architecture & Buffer Isolation

Detailed technical analysis of SSE multiplexing, file rotation mechanics, and client-side ring buffer isolation (Issue #639).

Core Architectural Problem: Spread Hunter runs concurrent background loops: high-velocity shadow rehearsals (generating 100+ events/sec to shadow-*.jsonl), the live execution loop (cycle_events.jsonl), and market filter scans (rerank.log). In the legacy dashboard, all feeds multiplexed into a single 200-element JavaScript array. Under asymmetric event velocity, high-frequency shadow simulation instantly evicted live fills from memory.

1. End-to-End Pipeline Architecture

PR #641 creates isolated pipelines from disk to DOM:

trader_loop.py runtime/cycle_events.jsonl
filter_loop.py runtime/rerank.log
shadow_run.py runtime/shadow-<id>.jsonl
⬇️ Tail streaming via independent file descriptors & rotation checks
dashboard/server.py (FastAPI SSE Router) Endpoints: GET /api/cycle-stream & GET /api/log-stream?source=<id>
Tracks per-connection offsets, inode rotation via _ring_replay_and_offset()
⬇️ Server-Sent Events (SSE) with replay on reconnect
tickerBuffers.live [max 200 slots]
tickerBuffers.filter [max 200 slots]
tickerBuffers.shadow [max 200 slots]
