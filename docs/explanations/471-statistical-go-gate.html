Issue #471 — the statistical GO gate

One question, decided by arithmetic rather than opinion: does this maker make money on average, after every loss it takes, with enough closes that the result is not luck? The gate answers it with a 90% confidence bound, and it is allowed to say “not enough evidence” instead of yes or no.

1The one-sentence rule

The gate

mean_return_pct − 1.645 · (stdev / √n) > 1.0
…computed over every close method — merges, stranded-leg exits, settlements — and it only counts if n ≥ 60 closes and 25 matured markouts.

Read it as: “the bad end of a 90% confidence interval still clears +1% of bankroll.” A run that merely makes a little money does not pass. A run that makes money on 40 closes does not pass either — it gets INCONCLUSIVE, which is a refusal to decide, not a soft yes.

GO

Powered sample + primary gate passes + pessimism survives (see §8).

Meaning: proceed to calibration/dry-live work.

NO-GO

Powered sample, gate fails. The strategy is losing on an inclusive basis.

Meaning: diagnose the exit path before any money moves.

INCONCLUSIVE

Not enough closes, not enough markouts, or no computable CI.

Meaning: run longer. This is not a pass and not a fail.

The distinction people get wrong

INCONCLUSIVE is not permission. Everything downstream reads GO or nothing. A 45-close run that looks profitable is a rehearsal, not a result — the memo says so in the only place that matters: the verdict line.

2The trap this gate exists to avoid

A completed pair always pays $1.00 for less than $1.00. So E[PnL | method=merge] > 0 cannot fail — it is a tautology dressed as evidence. The gate therefore runs over every close, including the ones that hurt: single_buy_exit, naked_exit, settlements, and gas.

3The arithmetic, worked on that sample

Nothing here is exotic: a per-close percentage return, a sample mean, a standard error, and one multiplier. The only opinion in it is the threshold, and that lives in config. 

# core_brain/kpi.py:292-325  (evaluate_stat_gate)
r_i     = 100 * realized_pnl_i / cost_basis_i      # skip closes with no cost basis
mean    = arithmetic mean of r_i
stdev   = sample stdev of r_i                      # n - 1
se      = stdev / sqrt(n)
lower   = mean - 1.645 * se                        # 1.645 = ci_z(90), one-sided 5% tail
passed  = lower > 1.0  and  (lower/100)*bankroll > bankroll * 0.01

Why +1% and not > $0

“Positive” is not the bar. Beating zero by a hair means the edge dies to one extra tick of slippage, and the pessimism column will show it (§8). The gate demands the bad end of the estimate clear 1% of bankroll, which at the $100 rehearsal baseline is $1.00. Config: core_brain/config.py:236-239 (threshold_pct=1.0, bankroll_pct=0.01, target_closes=60).

4The verdict ladder

The order of these questions is the design. Power is tested before profitability, because a thin sample must never be allowed to produce a GO or a NO-GO.

1 Is the sample powered? closes ≥ 60 and matured markouts ≥ 25. Either one short → INCONCLUSIVE. artifacts.py:284-286
2 Are there at least 2 closes? A confidence interval needs a variance. Fewer → INCONCLUSIVE. artifacts.py:287-294
3 Could a CI be computed at all? No close carries a usable cost basis → INCONCLUSIVE, never a silent pass. artifacts.py:301-310
4 Does the primary gate pass (strict >)? Yes → GO  |  no → NO-GO. Equality at 1.0000% is a FAIL by test. artifacts.py:311-327 · tests/test_stat_validation_artifacts.py:207
5 Does a GO survive pessimism? Only a GO is revisited: if the ask+1-tick column fails, the headline verdict is downgraded to that failure. A NO-GO never upgrades. artifacts.py:607-618
The one place verdicts can disagree with each other

Step 5 happens inside write_artifacts, which builds the memo and report.json. But the harness's stderr line STAT VERDICT: … (run.py:518-523) and run_result.json (run.py:458-474) are written from the pre-downgrade verdict. On a sample where base passes and pessimism fails, the console can print STAT VERDICT: GO while report.md says NO-GO. The memo is the decision; the console line is the raw gate.

Precision note

kpi.evaluate_stat_gate uses ≥ internally, while the artifact row uses strict > so that exactly 1.0000% reads as FAIL. The artifact comparison is the one wired to the verdict, so the strict rule is the operative one (artifacts.py:147-151), and a test pins it.

7Why 60 closes — and why more closes will not rescue a bad mean

A confidence bound narrows like 1/√n. That means sample size buys precision, not profit: it pulls the bound towards the true mean from both sides. If the true mean is negative, more closes make the NO-GO more certain, not less.

What 60 buys you

At n = 60 with stdev 46.27 the standard error is 5.97 points, so the CI half-width is about 9.8 points. A GO needs a mean above +10.8%. The gate is deliberately hard to pass on noise.

What 60 does not buy you

A verdict at small n is fragile in both directions: one 40% loss moves the mean by 0.7 points. That is exactly why 60 is a floor and 25 markouts must also mature — and why the memo prints the sensitivity column next to the verdict.

The markout requirement is the same idea applied to the book, not the P&L: 25 matured markouts prove the quotes were actually sampled at real horizons. Immature markouts read as insufficient_sample, never as “zero adverse drift” — a run that ends before its horizons mature cannot claim the book was clean.

8The pessimism column: can the GO be killed by one tick?

The base gate uses recorded fills. The pessimistic column asks the harder question: what if every taker-resolved close had paid one tick worse per share? That re-costs the same closes and rebuilds the whole distribution. 

# core_brain/kpi.py:1188-1211  (_pessimistic_close_return)
if method in TAKER_RESOLVED_METHODS:          # merges + single-buy exits
    penalty = shares * tick + gas             # tick = 0.01, gas = 0.00 today
    return 100 * (realized_pnl - penalty) / cost_basis
else:
    return 100 * realized_pnl / cost_basis    # untouched

On the real sample

-9.87%

pessimistic lower bound, vs -8.42% base — 1.44 points of extra drag. Both fail, so no downgrade drama here.

When it matters

On a passing base, the pessimism column is the difference between GO and NO-GO. The headline verdict is downgraded whenever base says GO but pessimism does not (artifacts.py:613-618), and a test pins that behaviour (tests/test_stat_validation_artifacts.py:454).

Why the tick is charged against every share in the pair

The store keeps one merged cost per completed pair, so the per-leg split — how many shares actually crossed at the ask — is not recoverable. The penalty is therefore applied to the pair's whole share count: a conservative upper bound. Erring against the strategy is the safe direction for a gate whose job is to prove the edge survives a worse fill. Gas is currently 0.0 (kpi.py:1178), so the measured drag is pure tick.

The uncomfortable arithmetic

Cutting the stranded-leg damage in half is not enough — that sample still lands at -2.77% lower bound. Only driving those exits to roughly break-even, or completing the pairs before they strand, clears the gate. If #471 runs on the current strategy it will most likely produce a NO-GO, and that NO-GO is a diagnosis: the maker edge is real, the rescue path is what bleeds.

Same counterfactuals also improve pessimism: with zero-cost exits the base lower bound is +2.40%, which still has to survive the ask+1-tick column before it is a GO.

11Runbook for the run #471 actually asks for

This is the operator-facing sequence. It spends nothing: the harness holds no signer, writes only to an isolated store, and refuses data/orders.db outright.

Pre-flight

  1. Sync main. Local main was one commit behind origin today (1074ea2a → 1617c3c8). Run git pull --ff-only before launching so the run's provenance matches the tree.
  2. Feed freshness. The harness refuses to start without a graduated market list (runtime/markets.json, run.py:392-400). If it is stale, python scripts/rank_markets.py first.
  3. Decide fresh vs resume. data/val_step3.db does not exist yet, so this run is a fresh sample. Re-running later with the same --run-id appends to it.

  • Rotation summary at the end prints quoted / declined / errors — a wall of DECLINED with zero closes means the filters, not the gate, are the topic.
