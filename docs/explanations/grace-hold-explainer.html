Why “grace” kept your orders alive

The refusal-hold path in core_brain/trader_loop.py — what it was, why it fired, and how it differs from the rescue grace you removed. Interim state 2026-10-16 (pending #622): the hold is OFF (REFUSED_HOLD_GRACE_CYCLES = 1), so the first transient refusal cancels. The walkthrough below shows the GRACE=3 behavior, restorable if #622 keeps the hold.

Short answer: there are two different things called “grace” in this codebase. You removed grace #1 (rescue patience on filled legs — dead, no reader). Grace #2 (hold-on-refusal, issue #390) kept resting orders through up to 3 consecutive refused cycles before cancelling — but it is currently OFF by interim operator directive (GRACE=1: first refusal cancels, pending #622). It is unrelated to the stop-loss spec either way.

1. The two graces — dead vs live

GRACE #1 — DEAD

Rescue patience (single_buy_grace_sec)

Gave a filled single leg N seconds as maker before rescue. Retired in #619: the env var now logs “retired and ignored” (config.py:1494-1511) and no code reads the knob. This is the one you remember removing. It cannot hold anything.

Leftover mentions: reason="grace_expired" labels on old closes, dashboard chips, two open cleanup rows — forensic text, zero behavior.

GRACE #2 — OFF (INTERIM, PENDING #622)

Hold-on-refusal (REFUSED_HOLD_GRACE_CYCLES = 1, was 3)

When the loop visits a market but decide refuses to quote (book flicker, not abandonment), resting orders cancel on the first refusal — no hold, no second chance. The 3-cycle hold below is the pre-2026-10-16 behavior, restorable by setting the constant back to 3 if #622 keeps the machinery. Lives in trader_loop.py:132.

Nothing to do with filled legs, rescue, or the stop-loss MD. It manages unfilled resting quotes.

3. The decision flow (exact code path)

Visit market, no intents. Lifecycle preserve-ids? → follow lifecycle, grace not involved. Otherwise:
▼ classify why — _classify_refusal (:135)
Terminal refusal (settled, expired, exited, unfunded…) → REFUSED_TERMINAL → cancel immediately via not_quoted. No grace, ever. (:426-433)
▼ else transient (wide book, cap, reward window…) → REFUSED_TRANSIENT
Streak check (:1900): refused_streak + 1 >= REFUSED_HOLD_GRACE_CYCLES?
At GRACE=3: No → HOLD — no cancel, no submit. Logs [HOLDING] … held through transient refusal.
Today (GRACE=1, interim): the very first refusal meets the threshold → REFUSED_GRACE_EXPIRED → cancel like terminal. (The #419 mid-hold band exception was removed 2026-10-16 — expiry now cancels everything.)
▼ after the visit
Streak counter (:808-820): held → streak+1, anything else → reset to 0. With the hold off, nothing is ever held by this path, so the streak never accumulates here — a single quoted cycle still wipes the count.

4. Why it exists (the churn it prevents)

From the comment at trader_loop.py:85-88: on shadow-02, 23 of 25 orders were cancelled with a median lifetime of 37s — mostly book flicker, not real abandonment. Cancelling on every refused cycle means:

  • paying cancel/replace churn on every book wobble,
  • losing queue position each time, then re-joining at the back.

The 3-cycle hold said: “the book moved, not the market — sit still until it's clearly dead.” A market that never comes back still cancelled on the 3rd consecutive refusal. The counter is per-market (refused_streaks[cid]), so one dead market can't spend another's patience. Currently off by interim directive (GRACE=1, pending #622) — the churn described below is what the loop pays today.
