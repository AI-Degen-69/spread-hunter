💡 במילים פשוטות: מה השתנה?

דמיינו חניון בלי שומר: מכוניות (הזמנות) נכנסות ונשכחות בלי בעלים. הבוט קודם היה שם רק מכוניות חדשות בחניון, בלי לבדוק אם יש שם מכוניות אבודות. עכשיו יש שומר חניון שעובר כל סיבוב: אם שתי מכוניות שייכות לאותו בעלים — הוא מחבר ביניהן. אם מכונית לא תהיה רווחית בשום מצב — הוא שולח אותה הביתה. ואם יש מכונית שכבר נמצאת בפנים בלי שום סיכוי להשלמה — הוא מפנה אותה בסדר. כך החניון (ההון) תמיד פנוי למכוניות שמביאות רווח.

🔄 לפני מול אחרי

🔴 לפני השינוי:

  • רגל שאיבדה את ה-pair_id נשארה תקועה לנצח — הון מת שלא עובד
  • שתי רגליים משלימות באותו שוק לא מזוהות כפאר — הבוט קונה פאר חדש במקום לאמץ את הקיים
  • הזמנות שאין להן סיכוי להפוך לפאר רווחי (>$1.00) נשארות על ספר ההזמנות ותופסות הון
  • פוזיציות חשופות (רגל אחת שנמלאה בלי שנייה) נשארות כהימור כיווני לא מכוון

🟢 אחרי השינוי:

  • אימוץ אוטומטי: שתי רגליים משלימות באותו שוק מקושרות תחת pair_id משותף כשהעלות < max_pair_cost
  • ביטול חסרי תקווה: הזמנות שלא יכולות להוליד פאר רווחי מבוטלות בבורסה + ברישום
  • סילוק פוזיציות חשופות: רגליים שנמלאו בלי שותף יוצאות דרך exit_single_buy במחיר שוק
  • בטוח ב-dry-run: עם --no-live רואים מה ישתנה בלי לגעת בכסף

⚡ זרימת התהליך החדש

01 · סריקה וסיווג

classify_market_orders

סורק את כל ההזמנות והפוזיציות הפתוחות בכל שוק. מסווג כל רגל לאחת מ-5 קטגוריות: paired, complementary, hopeless, viable, unhedged.

02 · פעולה לפי סיווג

adopt / cancel / remediate

רגליים משלימות → אימוץ לפאר. חסרי תקווה → ביטול בבורסה. פוזיציות חשופות → יציאה במחיר שוק. כל פעולה מתועדת עם סיבה.

03 · הון חופשי ונקי

reconciled state

אחרי הסיבוב: כל ההון או בפאר תקין שממתין למיזוג, או חזר לחשבון. אפס רגליים תקועות, אפס הימורים כיווניים בשוגג.

🕹️ מדריך בדיקה ידנית (Touch & See)

בדיקה מהירה להוכחת השינוי בעיניים ללא הרצת סוויטות טסטים:

1. הרצת Stray Guard ב-Dry Run

מריצים את השומר במצב יבש לראות מה הוא היה עושה:

python -m core_brain.order_manager stray-guard --no-live
מה אמורים לראות: דוח שמפרט adopt/cancel/exit שהיו מתבצעים — בלי ביצוע בפועל. כל שורה כוללת סיבה (למשל "combined cost $0.96 < $0.99").

2. הרצת Shadow Rehearsal מלאה

הרצת סימולציה שמוכיחה את הזרימה מקצה לקצה:

python -m core_brain.shadow_run --minutes 5
מה אמורים לראות: בלוג הריצה מופיעות שורות [stray-guard] שמסווגות הזמנות ומבצעות פעולות. אין שגיאות. הריצה מסתיימת בהצלחה.

3. בדיקת סטטוס ויתרה

בודקים שהמערכת מדווחת נכון:

python -m core_brain.order_manager status
מה אמורים לראות: סטטוס שכולל את מספר הפאריים הפעילים, יתרת החשבון, ואפס הזמנות יתומות.
