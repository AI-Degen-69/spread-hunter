במילים פשוטות

דמיינו שאתם רוצים לקנות ב-1 דולר. קודם יש מוכר שמציע יחידה ב-51 סנט, ואחריו עוד חצי יחידה ב-52 סנט. קודם היה המודל אומר: “קניתי 1.96 יחידות ב-51 סנט”. עכשיו הוא אומר את האמת: “קניתי 1.5 יחידות, במחיר ממוצע של כ-51.33 סנט”.

לפני ואחרי

לפני: מחיר מגע שטוח

  • הסכום חלקי מחיר המגע.
  • אין בדיקה של כמות זמינה בכל ask.
  • נוצר מילוי מלא גם כשאין מספיק עומק.
  • תוצאת החזרה נראית אופטימית מדי.

אחרי: הליכה לאורך asks

  • נלקחות רק רמות חיוביות עד 2 סנט מעל המגע.
  • כל רמה מוגבלת לפי ה-notional שנותר.
  • עומק דק מחזיר short fill במקום להמציא כמות.
  • המחיר, הכמות וה-markout שומרים את המילוי בפועל.

מדריך בדיקה ידני

הבדיקה היא על rehearsal בלבד. אין להריץ פקודת venue או פקודה שפותחת מסחר אמיתי.

1. להריץ את בדיקות ה-BUY הממוקדות

python -m pytest -q tests/test_exit_price_realism.py -k "buy"
מה אמורים לראות: בדיקות BUY ירוקות, כולל מילוי קצר, מחיר ממוצע, fallback ו-markout.

2. לבדוק rehearsal בלי כסף אמיתי

python -m core_brain.shadow_run --minutes 5
מה אמורים לראות: בדוח או ב-registry של הצל מופיעות השלמות BUY עם כמות ומחיר מילוי בפועל. כשספר ה-asks דק, הכמות קטנה מהחישוב השטוח והמחיר הממוצע משקף את הרמות שנלקחו.

3. לפתוח את ה-PR ולבדוק את שערי הפרויקט

Start-Process "https://github.com/AI-Degen-69/spread-hunter-live/pull/201"
מצב נוכחי: Ubuntu, Windows ו-GitGuardian עברו. ה-PR מוזג ל-main וה-Issue נסגר.
